# 운영 Runbook

## 매일 확인

1. 12:00~12:10 카카오 보고서 수신(스케줄러가 늦으면 22:00 전까지 따라잡음)
2. 미수신 시 대시보드 → ‘오늘 12:00 카카오 보고서’ 상태 확인

| 상태 | 원인 | 조치 |
|---|---|---|
| 카카오 발송 실패 + 재연결 필요 | refresh token 만료·동의 철회 | 알림 → 카카오 다시 연결 → 테스트 메시지 → “오늘 보고서 지금 보내기” |
| 카카오 발송 실패(HTTP 5xx/네트워크) | 카카오 일시 오류 | 10분 뒤 자동 재시도(최대 3회). 이후 수동 발송 |
| 보고서 없음 | Cron 미실행·잠금 | `npx wrangler tail`로 `scheduler_tick` 로그 확인 |

## 장애 유형별 조치

| 장애 | 조치 |
|---|---|
| GitHub 토큰 인증 실패(401) | 새 PAT 발급 → 연동 설정에 저장. 재연결 전 재실행 보류 |
| 권한 부족(403) | PAT 권한(Actions read/write)·저장소 범위 확인 |
| 호출 제한 | 자동 대기. 반복되면 감시 프로젝트 수·webhook 사용 검토 |
| 수집 실패 | 프로젝트 자체 실패가 아님. 연결 테스트로 원인 확인 |
| 예정 실행 기록 없음 | GitHub에서 워크플로 비활성(60일 무활동 자동 비활성 포함) 여부 확인 → 연결 테스트 경고 참고 |
| 게시 실패 | **재실행 전 플랫폼에서 실제 게시 여부 확인**(중복 게시 위험) |
| Heartbeat 서명 불일치 | secret 재발급 후 자동화 쪽 값 교체 |

## 로그

```bash
npx wrangler tail automatehq
```

로그에는 토큰이 남지 않게 마스킹된다. 오류 본문 원문을 찾지 말고 오류 코드로 판단한다.

## 백업

- 연동 설정 → 설정 내보내기(JSON, 비밀 값 제외)
- D1 Time Travel(무료 7일):

```bash
npx wrangler d1 time-travel info automatehq
```

## 비용 확인

Cloudflare 대시보드 Workers & Pages → automatehq → Metrics에서 요청·CPU를 확인하고, 필요하면 HQ 비용·사용량 화면에 수동 기록(MANUAL)한다.
